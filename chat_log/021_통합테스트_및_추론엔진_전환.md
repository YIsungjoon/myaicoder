## 1. 추론 엔진 전환 과정

### 1.1 문제: Qwen3.5 GGUF 아키텍처 미지원

Qwen3.5는 SSM(Mamba) + Attention 하이브리드 아키텍처(`qwen35`)를 사용한다.
2026-03-14 기준, 주요 추론 엔진의 릴리스 버전에서 이 아키텍처를 인식하지 못한다.

| 엔진 | 버전 | 에러 |
|------|------|------|
| vLLM | 0.17.1 | `ValueError: GGUF model with architecture qwen35 is not supported yet.` |
| llama-cpp-python | 0.3.16 (릴리스) | `unknown model architecture: 'qwen35'` |
| llama-cpp-python | master (GitHub) | `unknown model architecture: 'qwen35'` (vendor된 llama.cpp가 구버전) |

### 1.2 시도 과정

#### 시도 1: vLLM 0.17.1 (실패)

```bash
~/vllm-env/.venv/bin/vllm serve ~/models/Qwen3.5-9B-Q4_K_M.gguf --port 8001
# → ValueError: GGUF model with architecture qwen35 is not supported yet.
```

vLLM은 별도 가상환경(`~/vllm-env/`)에 설치했으나, Qwen3.5 미지원으로 사용 불가.

#### 시도 2: llama-cpp-python 0.3.16 릴리스 (실패)

```bash
uv pip install --python ~/vllm-env/.venv/bin/python "llama-cpp-python[server]"
~/vllm-env/.venv/bin/python -m llama_cpp.server --model ~/models/Qwen3.5-9B-Q4_K_M.gguf --port 8001
# → error loading model architecture: unknown model architecture: 'qwen35'
```

#### 시도 3: llama-cpp-python GitHub master (실패)

llama-cpp-python은 llama.cpp를 vendor(내장 복사본)으로 포함하는데,
이 vendor된 llama.cpp 버전이 아직 qwen35를 지원하지 않았다.

```bash
# 새 환경 생성
uv venv ~/llm-server-env --python 3.12

# GitHub master에서 CUDA 빌드 시도
CMAKE_ARGS="-DGGML_CUDA=on" uv pip install --python ~/llm-server-env/.venv/bin/python \
  --force-reinstall --no-cache-dir \
  "llama-cpp-python[server] @ git+https://github.com/abetlen/llama-cpp-python.git"
```

여기서 추가 문제 발생:

**CUDA 12.0 → Blackwell GPU 미지원**:
```
nvcc fatal: Unsupported gpu architecture 'compute_120'
```

RTX PRO 4000 Blackwell은 compute capability 12.0이며, CUDA 12.0의 nvcc가 이를 인식 못 함.

**해결**: CUDA 12.8 설치

```bash
wget https://developer.download.nvidia.com/compute/cuda/repos/ubuntu2404/x86_64/cuda-keyring_1.1-1_all.deb
sudo dpkg -i cuda-keyring_1.1-1_all.deb
sudo apt update
sudo apt install -y cuda-toolkit-12-8
echo 'export PATH=/usr/local/cuda-12.8/bin:$PATH' >> ~/.bashrc
echo 'export LD_LIBRARY_PATH=/usr/local/cuda-12.8/lib64:$LD_LIBRARY_PATH' >> ~/.bashrc
source ~/.bashrc
```

CUDA 12.8 설치 후 재빌드했으나, 구버전 nvcc(`/usr/bin/nvcc`, 12.0)가 PATH에 남아있어
CMake가 잘못된 nvcc를 사용하는 문제 발생. `-DCMAKE_CUDA_COMPILER=/usr/local/cuda-12.8/bin/nvcc`로
명시 지정하여 해결.

빌드는 성공했으나, 여전히 `unknown model architecture: 'qwen35'` — vendor된 llama.cpp가 구버전.

#### 시도 4: llama.cpp 직접 빌드 (성공!)

llama.cpp 본체(ggml-org/llama.cpp)의 main branch는 qwen35를 지원한다.

```bash
cd ~/llm-server-env
git clone https://github.com/ggml-org/llama.cpp.git
cd llama.cpp
cmake -B build -DGGML_CUDA=ON -DCMAKE_CUDA_COMPILER=/usr/local/cuda-12.8/bin/nvcc
cmake --build build --config Release -j$(nproc)
```

빌드 완료 후 서버 시작:

```bash
~/llm-server-env/llama.cpp/build/bin/llama-server \
  --model ~/models/Qwen3.5-9B-Q4_K_M.gguf \
  --host 0.0.0.0 --port 8001 \
  --n-gpu-layers -1 --ctx-size 32768
```

**결과**: Qwen3.5-9B가 GPU에 정상 로드, OpenAI 호환 API 제공 확인.

### 2.3 skip 테스트 전환

기존 `skipif(True)` (하드코딩) → 환경변수 기반으로 전환 완료:

```python
# 변경 전
@pytest.mark.skipif(True, reason="Integration test: requires running vLLM server")

# 변경 후
@pytest.mark.skipif(
    not os.environ.get("VLLM_INTEGRATION"),
    reason="Set VLLM_INTEGRATION=1 with running vLLM server on :8001",
)
```

실행 방법:
```bash
# 일반 테스트 (skip)
uv run pytest tests -q  # → 99 passed, 4 skipped

# 통합 테스트 포함
VLLM_INTEGRATION=1 uv run pytest tests/test_llm -q  # → 6 passed
```

## 6. 교훈 (Lessons Learned)

### 6.1 추론 엔진 선택

- Qwen3.5처럼 최신 아키텍처는 릴리스 버전에서 지원하지 않을 수 있다
- Python 바인딩(llama-cpp-python)이 vendor한 llama.cpp는 본체보다 뒤쳐진다
- **llama.cpp 직접 빌드가 가장 확실한 방법** — OpenAI 호환 API(`llama-server`) 제공

### 6.2 CUDA + Blackwell GPU

- Blackwell(compute_120)은 CUDA 12.8+ 필요
- 시스템에 구버전 nvcc가 남아있으면 CMake가 잘못된 버전 사용 → `-DCMAKE_CUDA_COMPILER` 명시

### 6.3 별도 환경 분리

- LLM 서버(llama.cpp)는 프로젝트 venv와 완전 분리 — 의존성 충돌 방지
- `~/llm-server-env/llama.cpp/`에 빌드, `~/models/`에 모델 — 인프라 자원끼리 모임
